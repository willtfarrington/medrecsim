# Release criteria (D-OSS-003, D-QA-002, D-EXEC-003)

**Status:** standing — every tag checklist starts from this file · **Instantiated:** 2026-09-02
(EP-5) from [roadmap/appendices/governance-security.md](../roadmap/appendices/governance-security.md)
§7 · **Executed at:** every `0.x` tag (per-tag checklist; first at `v0.1.0`, EP-19) and the
v1.0.0 audit (all twelve gates, EP-38) · **Changes to the gates:** owner-only, by a dated
DECISIONS.md entry.

Three things live here: the **twelve gates** that v1.0.0 must pass, the **0.x conventions**
that govern every tag before it, and the **per-tag checklist** that is run — and recorded —
at every tag, 0.x or 1.0. Releasing is an owner-only act (D-EXEC-003 "publishing beyond
repo/Pages"); an agent session prepares the checklist evidence and stops at the tag.

## 1. The twelve v1.0.0 gates

Each gate names what "pass" means, the artifact that proves it, and where the artifact lives.
A gate with any open item fails; "documented accepted risk" is allowed only where the gate
says so. The audit session (EP-38) fills the **Result** column with a date and a pointer, and
the completed table is committed with the tag.

## 2. Versioning and release conventions (0.x)

- **Semantic versioning, `0.x` throughout construction.** `1.0.0` is tagged only when all
  twelve gates pass and G12 is recorded (D-OSS-003). Nothing about a 0.x tag implies
  stability or validation; the README status line (CLAIMS C11) stays until 1.0.0.
- **Minor = feature slice.** `0.1.0` = R1, the vertical slice (one complete introductory case,
  deployed to Pages). Later minors correspond to the R2 slices and R3 hardening as the
  roadmap delivers them. A minor may also be cut when a new case or a new evidence channel
  ships, at the owner's discretion.
- **Patch = fixes and content.** Bug fixes, wording fixes, accessibility fixes, and content
  patches (including a D-RISK-004 freeze or resolution patch to a case bundle) are patches.
- **Three version streams stay separate** (D-DATA-002): the app version is the tag; the
  content-schema version (major.minor) is stamped in every bundle; each bundle carries its own
  content version. The changelog's **Content** category records bundle and schema version
  changes so a reader can reconstruct which content shipped with which app version.
- **Annotated tags + GitHub Releases.** `git tag -a vX.Y.Z` with the changelog section as the
  message; a GitHub Release is created from the tag with the same notes. Releases are the
  only publication channel besides the repository and its Pages deployment.
- **Keep a Changelog** format ([CHANGELOG.md](../CHANGELOG.md)), with the standard categories
  plus a custom **Content** category. The `[Unreleased]` section is always present; a release
  moves its entries under a dated version heading.
- **Pages deploys from `main` only**, gated on CI green; a tag never deploys by itself
  (THREAT-MODEL.md boundary B3). Tagging happens after the release commit is on `main` and
  deployed.
- **No calendar dates in the roadmap** (D-RISK-006); dates appear only in tags, the changelog,
  and CITATION.cff, after the fact.

## 3. Per-tag checklist

Run in full at every tag, 0.x and 1.0. The releasing session copies this list into the
releasing EP's handoff (or, for a patch release outside any EP, into the release notes) and
records each item's outcome with a date. Any unchecked item blocks the tag.

1. **Release commit on `main`, CI green on both OSes, Pages deployed** from that commit.
2. **Claims matrix check** ([CLAIMS.md](CLAIMS.md)):
   - Re-read every row. Flip each *Deferred* row whose named EP has landed to *Evidenced*,
     naming the artifact and the date. Any row that cannot be flipped and cannot be softened
     blocks the tag.
   - **README sweep:** map every outward README sentence to a row or mark it claim-free;
     record the mapping; fix any orphan by adding a row (owner-only) or removing the sentence.
   - **PR-template rule honored:** no outward claim was added since the last tag without a
     matching row (compare the diff of outward copy against CLAIMS.md since the last tag).
   - **Copy-rule grep** clean (rule statements that mention the forbidden phrase in order to
     forbid it are the only permitted hits, and they always carry the word "never" on the same
     line):

     ```
     git grep -n -i "expert-reviewed" -- README.md CONTRIBUTING.md SECURITY.md SUPPORT.md CODE_OF_CONDUCT.md THIRD-PARTY.md CITATION.cff CHANGELOG.md LICENSE-CONTENT.md ".github" "docs" "source material" "medrecsim" ":(exclude)docs/handoffs" ":(exclude)medrecsim/pnpm-lock.yaml" | grep -v -i "never"
     ```

     Expected output: nothing. The same rule runs in CI on every build
     (`medrecsim/scripts/check-claims.mjs`, EP-8), together with the disclaimer diff below.
   - **Disclaimer block byte-identical** in every consumer. For the README:

     ```
     diff <(sed -n '/^> Educational use only\./,/^> clinical use\./p' docs/CLAIMS.md) <(sed -n '/^> Educational use only\./,/^> clinical use\./p' README.md)
     ```

     Expected output: nothing. The in-app banner renders the block from
     `medrecsim/packages/app/src/disclaimer.json`; the app's own test and the CI claims check
     assert byte-equality with CLAIMS.md (EP-8). Pre-briefs (EP-19) must consume the same
     constant.
   - **Case counts (C9):** the README states the live numbers ("N published, M reviewed") and
     they match `content/`.
   - Record "claims: clean at `vX.Y.Z`, date" in the release notes.
3. **`CITATION.cff` bump:** `version` set to the tag, `date-released` set to the tag date;
   validated (`cffconvert --validate` or the GitHub "Cite this repository" control renders).
4. **`CHANGELOG.md`:** the `[Unreleased]` entries moved under `## [X.Y.Z] - YYYY-MM-DD`; a fresh
   empty `[Unreleased]` left above; the compare links at the foot updated; every Content entry
   names the bundle/schema versions it refers to.
5. **`THIRD-PARTY.md` regenerated** — inside `medrecsim/`: `pnpm build && pnpm notices`
   (the generated section is derived from the lockfile and the build's bundle manifest;
   `pnpm notices -- --check` reports drift without writing) — the diff committed with the
   release, the hand-maintained sections re-read, and `source material/REGISTRY.md` reviewed
   for new rows.
6. **Security baseline spot-check:** no open alerts without an accepted-risk entry; committed
   ruleset exports match the live rulesets.
7. **Name screen:** before `v0.1.0` specifically, NAME-SCREEN.md must carry the owner's
   official USPTO session (Run 3) as decided at EP-3; at every later tag, confirm no new
   collision report is open.
8. **Screenshots** in README/docs (if any changed): taken from Pages and leak-screened (G7).
9. **Owner approves the tag** (D-EXEC-003). For 0.x tags this is the owner's explicit go in
   the releasing session, recorded in the handoff; for 1.0.0 it is the G12 ledger entry.
10. **Tag and release:** annotated tag, GitHub Release with the changelog section as notes,
    release notes carry the claims result and the live case counts.

## 4. What is not a release

Pushes to `main` between tags are not releases, even though Pages redeploys from them; the
status line and the `[Unreleased]` section cover them. A content freeze patch under
D-RISK-004 is pushed immediately (safety first) and swept into the next patch tag.
